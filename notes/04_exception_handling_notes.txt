================================================================================
                   PYTHON CORE NOTES: EXCEPTION HANDLING
================================================================================

WHAT IS AN EXCEPTION? (In Simple Words)
An Exception is an error that happens while a program is running. When Python 
encounters an error (like dividing by zero or opening a missing file), it stops 
executing and "crashes". Exception handling is a way to tell Python what to do 
instead of crashing.

WHY DO WE USE IT?
- To prevent our program from shutting down abruptly.
- To handle bad user input gracefully.
- To display clear, friendly warning messages to the user instead of ugly system error codes.

================================================================================
                1. THE `try-except-else-finally` STRUCTURE
================================================================================
Python uses a special block structure to catch and handle exceptions:

```python
try:
    # 1. Place the code here that MIGHT crash.
    number = int(input("Enter an integer: "))
    result = 10 / number
except ValueError:
    # 2. This runs ONLY if a ValueError occurs (e.g. user typed "abc").
    print("Error: That wasn't a valid integer!")
except ZeroDivisionError:
    # 3. This runs ONLY if a ZeroDivisionError occurs (e.g. user typed 0).
    print("Error: You cannot divide by zero!")
except Exception as e:
    # 4. (Optional) Catches any other unexpected error and gets its description.
    print(f"An unexpected error occurred: {e}")
else:
    # 5. (Optional) Runs ONLY if the try block succeeded without any errors.
    print(f"Success! The result is {result}")
finally:
    # 6. (Optional) ALWAYS runs, no matter what, whether there was an error or not.
    # Ideal for cleanup tasks like closing files or database connections.
    print("Calculation process finished.")
```

================================================================================
                         2. COMMON BUILT-IN EXCEPTIONS
================================================================================
You should catch specific errors so you can handle them appropriately. Here are the most common exceptions:

1. ValueError:
   - Triggered when a function receives an argument of the right type but inappropriate value.
   - Example: `int("hello")` (Trying to convert text letters to an integer).

2. ZeroDivisionError:
   - Triggered when dividing any number by zero.
   - Example: `10 / 0`.

3. FileNotFoundError:
   - Triggered when trying to open a file that does not exist on your computer.
   - Example: `open("non_existent_file.txt", "r")`.

4. KeyError:
   - Triggered when searching for a dictionary key that isn't present in the dictionary.
   - Example: `student = {"name": "Aman"}` ➔ `student["age"]`.

5. IndexError:
   - Triggered when trying to access a list index that is out of range.
   - Example: `my_list = [10, 20]` ➔ `my_list[5]` (Indices 2 to 5 do not exist).

6. TypeError:
   - Triggered when an operation is applied to an inappropriate data type.
   - Example: `"hello" + 5` (Adding a string and an integer).

================================================================================
                            3. PRACTICE EXAMPLES
================================================================================

- Example 1: Safe Division Function
  ```python
  def safe_divide(a, b):
      try:
          return a / b
      except ZeroDivisionError:
          print("❌ Error: Cannot divide by zero!")
          return None
      except TypeError:
          print("❌ Error: Both inputs must be numbers!")
          return None
  ```

- Example 2: Safe File Reader
  ```python
  def safe_read_file(filename):
      try:
          with open(filename, "r") as file:
              return file.read()
      except FileNotFoundError:
          print(f"⚠️ Error: The file '{filename}' was not found.")
          return ""
  ```

================================================================================
                         CRITICAL RULES & BEST PRACTICES
================================================================================
* Avoid Bare `except:` Statements:
  - Do NOT write a plain `except:` without specifying error types. 
  - Why? It catches ALL exceptions including critical system exits (like `Ctrl+C` to stop a script), making debugging extremely difficult.
  - If you want a general fallback, use `except Exception as e:`.

* Catch Specific Exceptions First:
  - Put specific exception types (like `ValueError`) first, and general ones (like `Exception`) at the bottom. Python checks exceptions from top to bottom.
